# Deckhand — Project Handoff
(formerly "Classroom Clock")

## What this is
**Deckhand** (name chosen by Croix, Aug 2026 — the crew member who handles the deck; nautical, and it literally handles his Slides deck): a single-file HTML classroom tool (`Deckhand_v5.html`) built for Croix, a 7th grade math teacher at Windy Hill Middle School (Lake County Schools, FL — wolves, #OnePack; "HOWL Time" is their advisory block). It runs on his classroom machine, displayed on a **Promethean interactive touch panel**, alongside a presented Google Slides "Daily Math Board" deck. It exists because his school restricts Chrome extensions, ruling out the Slides Timer extension.

**Long-term vision (stated by Croix): a "classroom operating system"** — a family of live classroom tools in one file — while keeping every hard constraint below. It **complements** the Slides board, never absorbs it ("I can absolutely not compete with Google's own system"). OS scope is "things a slide can't be": live, ambient, or interactive. No static content, no daily-board duplication.

## Hard constraints — do not break these
1. **Single self-contained HTML file.** No build step, no separate CSS/JS at runtime (npm is for the TEST suite only). Runs by double-clicking on a locked-down school machine and from the Pages URL.
2. ~~No browser storage.~~ **RETIRED in v7.0** (Croix, Sep 25 2026): the board autosaves to localStorage (`deckhand.config`); the baked block is the seed; "Export a copy" is the backup/move path. Nothing ever leaves the machine.
3. **No external dependencies except Google Fonts** (DM Sans via `<link>`, `system-ui, sans-serif` fallback). Degrades gracefully offline.
4. **No extensions, no installs, no accounts.**
5. **Audio may be blocked** — the visual alarm must always work without sound.

## Current feature inventory (v6 — historical; see "State of the board" above)

**Canvas & scenes (v6)**: `main#canvas` holds absolutely-positioned widget cards (`container-type:size`; all inner type scales with `cqw/cqh/cqmin` clamps). Drag = pointerdown on the strip with `setPointerCapture`; resize = corner handle (min 180×140); both snap 48px in page coords and are ignored while locked, in the ≤780px stacked fallback (which force-stacks widgets statically), or from a second simultaneous touch (pointerId-filtered, one drag at a time). `removeEntry` splices the widget out of the scene config (the static `#clockWidget` is hidden, never removed — and `clearScene` hides it unconditionally so a saved clockless scene can't boot a ghost clock). `addWidget` cascades positions, refuses a 13th widget (dock buttons disable at the cap), allows one clock per scene, and picks the smallest unused auto-label so alarm names stay unambiguous. Scene switch tears down timers (`destroy()` clears timeouts/rAF); the scene dropdown blurs itself after a change so the keyboard always belongs to the board. **Compact fallback** (≤780px wide OR ≤540px tall — phones either orientation, tiny windows): widgets stack full-width at natural height (`container-type:inline-size`, since size containment needs a fixed height), page scrolls, handles/waves hidden, dock goes static below; drags are disabled there so stored coordinates can't be corrupted. First cut of this fallback chopped widgets to a fixed 320px — Croix caught it on his phone Aug 31 ("butchered my boy"); reworked same day.
**Landing page** (every open; it IS the weekly ritual): time-of-day greeting ("Good morning, Mr. Shaffer" — name in config, editable), date, **THIS WEEK'S BELLS** picker (Teal Week / Black Week / No bells chips), "Open the Daily Board" button. Keys: Enter/Space launch, 1–N pick (hint auto-matches), F/M work. "Home (H)" pill on the board returns.

**Week rotation (v5.1)**: `bell.autoWeek` + `anchorMonday` ("2026-08-31") + `anchorWeekName` ("Black Week"). Weeks alternate between the FIRST TWO groups from the anchor Monday (DST-safe parity; non-Monday anchors snap to their Monday); the landing pre-presses the computed chip. **Manual chip tap still overrides for the day**; groups 3–4 are manual-only picks. The switcher lives in Settings ("Rotate weeks automatically" + "Week of… is…" — anchor compared by slot index, so renames don't count as changes; turning rotation OFF preserves the current pick; explicit No-bells survives even a rotation change). **Weekend rollover guard**: a machine left running adopts the new week at the date change unless a manual override is active (`deckhand:weekchange` event refreshes landing chips).

**Day sequence strip (v5.1, Croix's "which class next" tool)**: under the bell bar, the day's block order as small chips — past faded, current turquoise, next dashed during passing. Kills the Black-week "wait, what's next?" confusion (the day runs 6th→5th→…→1st). Toggle in Settings ("Day sequence strip", `bell.showDayStrip`). Labels rendered via textContent (user config = no HTML).

**Bells**: **Wednesday compression is automatic** (`getDay()===3` + non-empty wednesday blocks; readout shows "(Wed)"). Clock-card readout "Teal Week · 2nd · 39:00 until bell" + thin turquoise progress bar (sand during passing: "… · Passing · 3rd in 2:00"). Pre-school window 90 min. After last bell/no pick: hidden. **Nudge ±600s** shifts bell math only, never the clock. Weekend days simply follow the picked group's regular times (harmless; he can pick No bells).

**Timer widgets** (v6: multiple instances; S selects, no more tabs — stopwatch is its own widget): presets from config (chips). Calculator-style entry on the SELECTED timer: stopped, type digits (7,3,0 → shows raw "0:73" = 73s, normalized on start); Enter/Space/Start commits (becomes new Reset target, deselects chips); Backspace edits; Esc cancels; digits inert while running (hint adapts). +1:00 works while running (visMax ratchet keeps visuals truthful). Last 10s coral. Background timers keep running and ring. Full-screen coral "TIME'S UP" + the ringing timers' names + 3-tone chime (660/660/880); click/Space/Esc/Enter dismisses and resets all ringing timers.

**Settings panel** (proper modal: focus moves in, Tab trapped, Esc closes, focus restored): display name, "Bells at startup" select (may be No bells), nudge, presets (1–6 values, 1–120 min), progress-bar + sound checkboxes (sound applies live AND at startup), **4 week-group editors** (name + regular textarea + optional Wednesday textarea; line format `label start-end`; times 6:00–11:59 AM / 12:00–5:59 PM; empty regular = removed; Wednesday-without-regular rejected; duplicate names rejected; validation atomic — any error applies nothing). Apply keeps the current week pick by name, then slot (renames survive); explicit No-bells picks are never resurrected.

**Download configured copy** (in Settings): the file re-serializes itself — pristine `outerHTML` snapshot at boot, config block regex-swapped, Blob download named `Deckhand_v6_YYYY-MM-DD.html` (real date even in SIM). Post-replace verification aborts rather than download stale config. Byte-stable across generations. This is how layouts persist: arrange, lock, download, replace the daily-driver file.

**Config** (`<script id="deckhand-config" type="application/json">` near top of file, hand-editable): schemaVersion 4 — `ownerName`, `ui{locked}`, `activeScene`, `scenes[{name, widgets[{type: clock|timer|stopwatch|bell, x,y,w,h (% of canvas), label}]}]`, `sound{enabled,volume}`, `clock{showSeconds}`, `timer{presetsMinutes,defaultSeconds,style}`, `bell{…, defaultGroup, groups[{name, regular[], wednesday[]}]}` (max 4 groups). Boot pipeline: parse → **migrate** (chain 1→2→3→4; v1 `bell.enabled:false` → defaultGroup "none"; v2 pairs "X Regular"+"X Wednesday" → "X Week", unpaired keep names, defaults map exact-name-first; 3→4 just bumps — sanitize supplies default scenes/ui; string schemaVersions tolerated) → **sanitize** (every field type-checked with per-field fallback; group/scene names deduped; scene coords clamped; ≤8 scenes × ≤12 widgets, one clock each; corrupt JSON → defaults with bells off). Each module boots in its own try/catch — nothing can take the clock down.

## Engineering practices (keep these)
- Timer accuracy from `endAt`/`startedAt` timestamps re-read on a 200ms repaint — never decremented counters; `visibilitychange` re-syncs countdown, stopwatch, and bell readout.
- ONE AudioContext, created/resumed on first gesture (capture listeners), reused; last-chance resume at ring.
- Pointer events + blur-after-pointer-click on all buttons (Promethean touch works; Space-after-click can't re-fire the button; keyboard activation keeps focus for a11y).
- Alarm overlay (z-30, above settings z-20) swallows ALL plain keydowns incl. auto-repeats; `e.repeat` guarded below it.
- Keyboard priority: alarm → repeat guard → settings Tab trap → form fields → settings → landing → selected-widget entry → entry-start → globals (Space/R act on the selection; S cycles selection; F/M/H). Dock buttons and the scene select blur after pointer use so shortcuts never die parked on a control.
- QA pipeline per release: Playwright suite against `file://` (currently **71 tests**: bell math against real times, canvas drag/resize/snap/z-order, scenes, lock, multi-timer routing, migrations via inline fixtures, settings atomicity, focus trap, hostile configs, download round-trip) + screenshot review + fresh-context adversarial review agent, findings fixed with regression tests.
